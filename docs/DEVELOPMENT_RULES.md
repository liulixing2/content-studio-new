# 开发规则

## 1. 低消耗原则

默认采用最低额度消耗方式：

- 不主动联网。
- 不主动调用 DeepSeek。
- 不主动生成图片。
- 不主动跑大范围扫描。
- 不主动做长时间任务。
- 能用 mock 验证就不用真实 AI。

涉及 DeepSeek、联网、图片生成、视频下载、批量生成前，必须先说明预计消耗和用途，并等待用户确认。

同一个操作连续失败 3 次后必须停止，不能继续自动尝试。

停止时必须说明：

- 当前失败的是哪一步。
- 已经尝试过哪些修复。
- 最新错误信息是什么。
- 建议下一步怎么处理。

这个规则同时适用于 Codex 操作、DeepSeek 调用、热点抓取、图片生成、视频处理和批量任务。

## 2. AI 调用规则

所有 AI 调用必须由用户点击按钮触发。

禁止：

- 页面加载自动调用 AI。
- 后台自动循环修稿。
- 抓取失败后自动改用本地兜底。
- 未确认就批量生成章节或视频内容。

必须：

- 调用前显示用途。
- 显示剩余调用次数或预计消耗。
- 保存 Prompt 和返回结果。
- 失败时给出明确错误。
- 自动修复必须有次数上限。
- 同一任务连续失败 3 次后停止，等待用户确认。

## 3. 保存规则

生成内容默认进入临时预览区。

只有用户点击“保存到作品库”后，才写入数据库。

不能自动保存：

- 失败内容。
- 半成品。
- 未通过质检内容。
- 用户未确认内容。

保存时必须生成版本记录。

## 4. 旧项目隔离

新项目不引用旧项目代码。

旧项目只放在 `_legacy_disabled` 中作为历史备份，不参与运行。

如果需要借鉴旧项目功能，必须重新设计接口和数据结构，不能直接复制旧模板逻辑。

## 5. 本地兜底规则

本地兜底必须明确提示。

例如：

```text
无法抓取网络热点，是否采用本地素材库？
```

不能把本地素材库伪装成网络热点。

## 6. 版权和素材规则

公众号配图默认不使用：

- 未授权影视截图。
- 动漫原片截图。
- 官方海报。
- 明星照片。
- 高度还原角色脸的图片。

视频素材必须记录来源。

项目可以提供素材抓取和下载工具，但是否有使用权限由用户确认。

## 7. 注释规则

需要注释：

- AI 调用封装。
- 调用额度限制。
- 保存和版本逻辑。
- 模板渲染关键逻辑。
- 文件上传和导出逻辑。
- 视频剪辑时间线逻辑。
- 版权风险处理逻辑。

不需要注释：

- 简单变量赋值。
- 普通表单绑定。
- 明显的 CRUD。
- 重复解释代码字面意思。

注释应该解释为什么这样做，而不是重复代码在做什么。

## 8. 测试规则

第一阶段测试以本地 mock 为主。

优先测试：

- 生成结果不自动保存。
- 点击保存后才进入作品库。
- 旧模板词不被放行。
- AI 调用不会自动触发。
- 手动模式可以生成 Prompt。
- API Key 不会写入 Git。

不默认测试：

- 真实 DeepSeek 调用。
- 真实平台下载。
- 大批量生成。

## 9. Git 规则

提交前确认 `.gitignore` 覆盖：

- `.env`
- `data/`
- `storage/`
- `logs/`
- `node_modules/`
- Python 缓存
- 前端构建产物

重要版本同时推送：

```bash
git push github main
git push gitee main
```
