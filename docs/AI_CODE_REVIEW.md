# AI 生成代码审查说明

## 目标

后续如果使用 AI 生成代码，需要人工审查后才能合并进项目。

重点不是代码能不能跑，而是是否符合项目规则。

## 必查项

### 1. 是否偷偷调用 AI

禁止：

- 页面加载时自动调用 DeepSeek。
- 后端启动时自动调用 DeepSeek。
- 失败后无限重试。
- 批量任务未确认就执行。

必须：

- 用户点击按钮才调用。
- 调用前显示用途和预计消耗。
- 调用次数有上限。

### 2. 是否自动保存半成品

禁止：

- 生成草稿自动入库。
- 失败内容自动入库。
- 未确认内容自动入库。

必须：

- 临时预览和作品库分开。
- 只有保存按钮写入数据库。
- 保存时生成版本。

### 3. 是否泄露密钥

禁止：

- 把 DeepSeek Key 写进代码。
- 把 `.env` 提交到 Git。
- 在日志里输出完整 API Key。

必须：

- 从环境变量读取 Key。
- `.env.example` 只放空值示例。

### 4. 是否复用旧项目模板

禁止：

- 复制旧项目生成模板。
- 复制旧兜底热词逻辑。
- 把本地素材伪装成网络热点。

必须：

- 新项目独立实现。
- 本地兜底必须明确提示。

### 5. 是否命名清楚

函数和变量应见名知意。

推荐：

- `generateTemporaryArticleDraft`
- `saveArticleToLibrary`
- `render_article_template`
- `selectedDirection`

避免：

- `doIt`
- `handle`
- `data1`
- `tmp2`

### 6. 是否有必要注释

需要注释：

- AI 调用控制。
- 保存规则。
- 版本规则。
- 模板渲染。
- 版权风险。

不需要注释：

- 普通赋值。
- 简单循环。
- 明显 CRUD。

### 7. 是否破坏目录边界

禁止：

- 在 `views.py` 里堆大段业务生成逻辑。
- 在前端组件里直接拼接所有接口地址。
- 把公众号、视频包、小说逻辑混在同一个文件。

必须：

- 后端 `views.py` 只负责请求和响应编排。
- 后端业务逻辑放在 `services/`。
- 前端接口走 `src/api/http.ts` 和具体业务 API 文件。
- 页面放在 `src/views/`，可复用局部 UI 放到页面自己的 `components/`。

### 8. 是否可发布检测闭环清楚

后续接 DeepSeek 后，必须确认：

- 生成内容先进入临时预览。
- 检测不通过时只生成修改建议，不直接覆盖用户已保存内容。
- 自动修稿有最大次数。
- 每次修稿都保存 AI 请求记录，方便追查问题来源。

## 审查结论格式

建议每次审查按这个格式：

```text
结论：通过 / 需要修改 / 不可合并

问题：
1. ...
2. ...

风险：
- ...

建议：
- ...
```
